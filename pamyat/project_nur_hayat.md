Nur Hayat — исламское PWA-приложение (React + Vite + Supabase), рабочий каталог: C:\Users\1\Pictures\nur-hayat

## Что сделано
- Авторизация + профиль (Supabase Auth)
- Полный Коран 114 сур (SuraPage, QuranPage)
- Времена намазов с GPS + кибла с компасом (PrayerPage)
- Тасбих счётчик
- Живой чат с комнатами (ChatPage, Supabase Realtime)
- Система достижений (ProfilePage — бейджи)
- История намазов с календарём (PrayerCalendar)
- 3 уровня пользователя: seeker / growing / practicing (OnboardingPage)

- Страница знаний (LearnPage): азкары, 99 имён, дуа, исламский календарь, гид намаза, Рамадан, арабский алфавит, разучивание сур, Q&A

## Система НУР (очки) — src/utils/nur.js
Уровни: Искра (0-100) → Путник (101-300) → Ищущий (301-700) → Верующий (701-1500) → Нур (1501+)

**Начисление НУР (все уровни):**
- Ежедневный вход: +15 (claimDailyLogin, раз в сутки, ключ localStorage)
- Каждый намаз: +10 (PrayerPage)
- Все 5 намазов в день: +30 бонус (PrayerPage)
- Стрик кратный 7: +100 (HomePage)
- Прочитал суру Корана (первый раз): +5 (SuraPage)
- Сообщение в чате: +3 (ChatPage)
- Открыл букву алфавита: +5 (QuranAlphabet)
- Прослушал все буквы: +10 (QuranAlphabet)
- Выучил суру: +50 (SurahLearn)
- Шаг пути новичка: +20 (BeginnerPath, только seeker)

**Milestone попапы:** при достижении 101, 301, 701, 1501 НУР — custom DOM event `nur-milestone` → NurMilestoneModal в App.jsx

## Ключевые файлы
- src/utils/nur.js — система НУР

**How to apply:** При добавлении новых действий использовать addNur(amount, user, profile, setProfile). Milestone автоматически всплывает.

## Инфраструктура: прокси, сертификат, сторож (обновлено 2026-08-11)
- **DNS**: 2026-08-11 удалены AAAA-записи (IPv6 `2a00:f940:2:2:1:1:0:293`) для `nurhayat.ru` и `www.nurhayat.ru`. Сервер по IPv6 недоступен («Network is unreachable» с телефона), а телефоны на мобильных сетях пробовали его первым и ждали впустую — отсюда были долгие загрузки, «не находит город», ложные подсказки про VPN. Записи AAAA у `ftp/mail/smtp/pop` оставлены намеренно. Зона живёт в ISPmanager → «Управление DNS» (NS = ns1/ns2.hosting.reg.ru), НЕ в разделе «Домены» на reg.ru.
- **SSL**: 2026-08-11 авария — сайт отдавал самоподписанный сертификат `nurhayat.ru_le3`, хотя настоящий Let's Encrypt `le2` был выпущен ночью. Приложение было отрезано от сервера несколько часов. Починка = переключить сайт на `le2` в ISPmanager → SSL-сертификаты. Истекает **2026-11-08**. Продление обычно срабатывает, ломается ПРИВЯЗКА сайта к новому сертификату.
- **Сторож** `supabase/functions/watchdog` + cron каждые 5 мин: проверяет прокси, шлёт push+письмо ТОЛЬКО разработчику (`ALERT_USER_ID`/`ALERT_EMAIL` в секретах). Предупреждает об истечении сертификата за 14/7/1 день. Дата хранится в таблице `service_health`, обновляется вызовом функции с телом `{"certExpiresOn":"ГГГГ-ММ-ДД"}` — из сертификата её не вычитать, edge-функции не отдают подробности TLS.
- **Запасной путь**: `src/supabase/client.js` при отказе прокси уходит на прямой адрес Supabase (достаётся из anon-ключа). Гонка с задержкой 3 с включена ТОЛЬКО для GET — дублировать запись нельзя. Проверка «прокси отдаёт заглушку» смотрит и на content-type, и на непустое тело: PostgREST на INSERT отвечает 201 с пустым телом и типом text/html, и наивная проверка уводила весь трафик мимо прокси.

**Why:** Все три проблемы (сертификат, IPv6, ложное переключение) выглядели как «приложение тормозит/не работает», но лежали в разных слоях и ни одна не была видна из кода.
**How to apply:** При жалобах «долго грузит / не находит город / нужен VPN» — сначала проверять сеть и DNS, а не код: `nslookup -type=AAAA`, `adb shell ping`/`ping6` с телефона, состояние сертификата через `openssl s_client`.
