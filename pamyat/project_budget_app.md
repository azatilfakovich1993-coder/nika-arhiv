Новый проект "Бюджет" — личный учёт доходов/расходов для пользователя, жены и пары знакомых (у каждого изолированные данные). Путь: `C:\Users\1\Pictures\budget-app`. Стек: React 18 + Vite + JS (без TS) + react-router-dom + Supabase + vite-plugin-pwa, без UI-фреймворка (свой CSS, мобильный-первый).

**Авторизация — имя + 6-значный PIN, без email**, поверх настоящего Supabase Auth: email генерируется детерминированно транслитерацией имени (`src/lib/translit.js`, `nameToLoginEmail`), PIN = пароль (6 символов = минимум Supabase). Реальная сессия Supabase → RLS работает через `auth.uid()` как обычно, никаких кастомных хаков.

**Главная фича UX** — быстрый ввод операции в 2 шага: открыл приложение → сразу крупный экран суммы с цифровой клавиатурой (переключатель Расход/Доход) → следующий экран — выбор категории (сетка, можно создать свою) → сохранение → переход на Главную. Это центральный, самый частый поток, ему отдан корневой роут `/`.

Реализовано (первая итерация, см. план `modular-prancing-lantern.md`): вход/регистрация, быстрый ввод (QuickEntry → CategoryPick), Главная (баланс за месяц), История (фильтры), базовая Аналитика (разбивка по категориям за месяц), Профиль.

**Сознательно отложено** на следующую итерацию: цели накоплений с дедлайном и авто-расчётом суммы в месяц/неделю, учёт кредитов, более глубокая аналитика (по дням/времени, тренды). Не начинать эти модули без отдельного запроса — решение принято явно, чтобы не делать недоделанные фичи.

**Для запуска нужен отдельный Supabase-проект** (ещё не создан на момент записи) — схема в `supabase/schema.sql`, переменные в `.env` (см. `.env.example`): `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON`. Без них приложение показывает экран "Supabase не настроен" вместо краша (см. `SB_ENABLED` в `src/supabase/client.js`).
